How it works

  1. 1

    Drop a reference image

    A photo, a sketch, a screenshot — any single image of what you want to model.

  2. 2

    Refine the photo if needed

    Built-in editor: remove background, inpaint a missing part, paint over an unwanted element, clone-stamp a detail. Get a clean reference before generation.

  3. 3

    AI engine generates the mesh

    The pipeline produces geometry, unwraps UVs and paints PBR textures in one pass. A few minutes of GPU time.

  4. 4

    Polish the mesh

    Retouch the texture directly on the 3D model, fix face artefacts, re-paint zones, regenerate parts. All in the same app — no Blender round-trip required.

  5. 5

    Export ready-to-use GLB

    Import straight into Unreal, Blender, Unity, Godot. Yours to use, sell, or remix.

Generation is half the work. Editing is the other half.

Most tools stop at generation and leave you to fix things in another app. MyFabmesh.AI puts the editor inside — for both the photo you start from and the mesh you end up with.

📷 Photo editor

Remove background · paint over · inpaint missing parts · clone stamp · mask zones · blur · crop. Get a clean front-view before you generate.

🪞 Mesh editor

Paint textures directly on the 3D model · regenerate broken zones · fix face artefacts · refine UV islands · 4K then 8K upscale · re-texture from a new reference.

🔁 Iterative loop

Generate · spot the issue · fix it · regenerate just that part. No round-trips to Photoshop and Blender between every iteration.

FAQ

Can I use AMD or Intel GPU for Desktop?

No, Desktop requires NVIDIA. AMD Radeon, Intel Arc, and integrated graphics are not supported locally. Use Cloud instead — it runs from any browser and works on any GPU.

Will it work on my MacBook?

The Desktop app is Windows only. On Mac, use the Cloud version directly from Safari.

Why 8 GB of VRAM?

The AI engine needs to load several large neural networks at once (mesh generation + texture synthesis + back-view + face refinement). Below 8 GB the app would crash. With 12 GB or more, you unlock the "Full" mode with face refinement and 8K textures.

Are the generated meshes mine to sell?

Yes, 100%. We use only AI models with commercial-safe licenses (MIT, Apache 2.0, BSD, OpenRAIL++-M). You own your output and can sell it on Fab, Sketchfab, Unity Asset Store, or anywhere.

Can I drive the app from VS Code or Claude Code?

Yes. The desktop app exposes an MCP (Model Context Protocol) server on first launch. Any MCP-compatible client — Claude Desktop, Claude Code in VS Code, Continue, etc. — can connect locally and issue commands: generate from an image, batch-process a folder, edit a texture, export a GLB. No API keys, no subscription, no cloud round-trip — everything runs on your machine through the same engine the GUI uses.

Can it pipe assets directly into Unreal Engine?

Yes — if you also install the Unreal Engine MCP plugin (community-maintained, free). Then a single Claude prompt can: (1) ask MyFabmesh.AI to generate or refine a mesh, (2) ask Unreal to import the resulting GLB at a chosen path, (3) spawn it as an actor in your level. The whole loop — image → mesh → engine → in-scene — runs without leaving the chat. Same trick works for Blender, Unity (if you wire their MCP bridges) or any tool with an MCP server.

Why does Windows say "Unknown publisher" when installing?

We're a young indie studio and the beta is unsigned. The installer is safe — you can verify the source on our GitHub. Click "More info → Run anyway" on the SmartScreen warning. The signed v1.1 (Azure Trusted Signing) ships as soon as we hit the milestone for the certificate.

I get a DLL load error blocked by "Application Control"

Windows 11's Smart App Control (a stricter policy than SmartScreen) blocks unsigned native libraries on first launch. This will be fixed for everyone in v1.1 once we sign every binary with Azure Trusted Signing. In the meantime: v1.1 is the right fix, we don't recommend disabling Smart App Control (it's permanent and weakens your PC). If you can't wait for v1.1, your safest option is to use the Cloud version instead — no install, no DLL, no policy issue.
