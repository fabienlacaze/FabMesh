# FabMesh Audit Report — 2026-05-29

## Executive summary
- Biggest risk: payment-correctness drift on the cloud worker — subscription renewals never credit users ([worker.ts#L3282](cloud/src/worker.ts#L3282)) and a silent INSERT error path can swallow a paid Stripe session with no retry ([worker.ts#L3203](cloud/src/worker.ts#L3203)).
- Biggest opportunity: a single renderer↔worker contract fix (camelCase `assetType` vs snake_case `asset_type`) restores correct asset-type-aware mesh pipelines for every non-character generation on cloud ([index2.js#L7096](cloud/public/app/index2.js#L7096) / [worker.ts#L3410](cloud/src/worker.ts#L3410)).
- Most cleanup wins concentrate in `worker.ts` (R2 JSON helpers, cookie helper, JSON body parser) and three near-identical client-result POST blocks in `index2.js`.

## Critical (data loss / security compromise)
(none confirmed)

## High (user-visible bug / blocking)
- Subscription `invoice.paid` reads wrong metadata path — recurring subscribers receive zero credits, every cycle. [worker.ts#L3282](cloud/src/worker.ts#L3282) — read metadata from `subscription_details.metadata` or fetch the Subscription explicitly.
- `handleGenerate` catch refunds credits but not `refundMeshSpend()` — failed Modal/Replicate mesh-starts permanently burn the daily GPU budget (Replicate default ≈ 1 failure = full lockout). [worker.ts#L3674](cloud/src/worker.ts#L3674) — mirror the addCredits + refundMeshSpend pattern used elsewhere in this file.
- Renderer sends `assetType` (camelCase) but worker reads `asset_type` — every non-character cloud generation silently runs the character pipeline (wrong rectify mode, wrong back-view dispatch, wrong credit defaults). [index2.js#L7096](cloud/public/app/index2.js#L7096) — rename the key in either the renderer or the FormData shim.
- `meshTool` ships positional arrays through `Object.assign({}, params)` so the worker reads numeric keys; smooth/decimate/subdivide cloud sliders are silent no-ops and the user is billed 1 credit per call. [meshyAPI-cloud.js#L1469](cloud/public/app/meshyAPI-cloud.js#L1469) — translate per-op array → named-object before posting, or rewrite `MESH_TOOL_SCHEMAS.*.build` to return objects.
- `cancelJob` sends the local UI counter id to `/api/jobs/cancel`; worker returns 404, Replicate keeps spending and credits are never refunded. [index2.js#L12918](cloud/public/app/index2.js#L12918) — store `created.jobId` on the pushed job and forward that instead of `state.jobIdCounter`.
- "Add back photo" calls `saveBuffer({buffer, subdir})` which falls into the legacy download branch; `backImagePath` becomes a local filename string, multi-ref TRELLIS-2 fails downstream. [index2.js#L1955](cloud/public/app/index2.js#L1955) — route through `API.saveImageDataUrl` (or teach `saveBuffer` to upload when `subdir` is provided).
- `applyOverrides` re-runs on every Settings/About click and keeps adding click listeners, MutationObservers, `setInterval`s, and wrapping `__cloudCreditsRefresh` into ever-deeper closures → N+1 chained `/api/me` calls per credit refresh. [cloud-overrides.js#L2141](cloud/public/app/cloud-overrides.js#L2141) — guard `_wrapTopbarRefresh` / `_watchModalOpens` / `installModalStatusPoll` / the timer registrations with idempotent flags or split into one-shot init + cheap reapply.

## Medium (impact present but not blocking)
- Stripe webhook `_processPayment` swallows all INSERT errors as "race won" and returns ok=true — transient Supabase failure on the same-invocation INSERT loses the payment silently (no Stripe retry). [worker.ts#L3203](cloud/src/worker.ts#L3203) — only treat Postgres `23505` as the benign race; everything else → `{ok:false, retry:true}`.
- Marketplace image publish authorises by substring-matching the attacker-supplied URL — accepts off-platform hosts, enabling bait-and-switch content laundering through `/api/market/download` after admin approval. [worker.ts#L1812](cloud/src/worker.ts#L1812) — reuse `_isTrustedImageHost` + `startsWith` prefix check + reject non-https.
- SSRF: 8 handlers forward user-controlled `imageUrl`/`meshUrl` to Modal with no host allowlist (asymmetric with `handleGenerate`). [worker.ts#L5192,L5273,L5352,L5446,L5506,L5930,L6053](cloud/src/worker.ts#L5192) — hoist `_isTrustedImageHost` to module scope and call it in every Modal forwarder; `handleMeshOp` is the highest-risk one.
- Desktop `pushJob` is missing the cloud `opts` snapshot — Job Details modal shows the wrong source thumbnail when the user switches selected image mid-job (the "knight thumb for porte-avion" bug, already fixed on cloud). [index2.js#L10110](src/renderer/index2.js#L10110) — port cloud's 6-arg signature and the `j.sourceImageUrl` priority in `refreshJobDetailsModal`.
- Three near-identical chunked-base64 → `/api/mesh-op/client-result` POST blocks; sites 2/3 already hardcode `opType:'center'` despite being semantically different ops — divergence is starting. [index2.js#L8255](cloud/public/app/index2.js#L8255), [#L10142](cloud/public/app/index2.js#L10142), [#L10750](cloud/public/app/index2.js#L10750) — extract `uploadClientMeshResult(bytes, opType, ...)`.
- 12× duplicated R2 list-pagination skeleton with already-divergent error policy (one site warns, others swallow). [worker.ts#L1272,L1375,L1426,L1490,L1533,L1558,L1662,L1756,L2075,L2110,L2201,L3319](cloud/src/worker.ts#L1272) — async-generator `r2ListJson<T>(env, prefix)`.

## Low / cleanup
- `market_sale` notification hardcodes `(+X credits earned)` even when seller was paid cash via Stripe Connect → support-ticket bait. [worker.ts#L2889](cloud/src/worker.ts#L2889) — branch the message on `paidCash`.
- `listing.downloads` counter race on R2 (read-modify-write of full listing JSON) — lost increments + tiny window where a download can resurrect a freshly-rejected listing. [worker.ts#L2994](cloud/src/worker.ts#L2994), [#L2906](cloud/src/worker.ts#L2906) — separate counter key or etag conditional put.
- `handleAdminMarketDelete` leaves orphan `_market/owners/*` and `_market/ratings/*` records (rating walker scans them forever). [worker.ts#L3003](cloud/src/worker.ts#L3003) — list-and-delete the two prefixes after the listing JSON.
- `handleUploadMesh` daily cap is GET→compare→PUT(+1) with no CAS — determined user can double/triple 200/day by parallelising. [worker.ts#L5837](cloud/src/worker.ts#L5837) — DO/etag-conditional put, or accept and raise the cap.
- `handleGenerate` doesn't inspect the jobs-row INSERT error; on partial Supabase failure Modal is still called, UPDATE silently no-ops, renderer gets "job not found" with credits gone. [worker.ts#L3624](cloud/src/worker.ts#L3624), [#L3693](cloud/src/worker.ts#L3693) — capture `{error}` and refund before calling Modal.
- `handleAdminContactReply` never clears `replied_read`, so a second admin reply never re-flags as unread. [worker.ts#L1616](cloud/src/worker.ts#L1616) — set `m.replied_read = false` on every reply write.
- Marketplace checkout has no per-(user, listing) idempotency — two completed Stripe checkouts for the same listing produce two paid sale rows and a double seller payout. [worker.ts#L2728](cloud/src/worker.ts#L2728) — HEAD owner key inside `_processMarketPurchase` before writing sale/payout, and/or Stripe `idempotency_key`.
- Inbox poller scans all `_meta/contact/` objects per 30s tick per logged-in user — O(N·M) per minute, will become real cost as contact volume grows. [worker.ts#L1537](cloud/src/worker.ts#L1537) — write a `_meta/contact_by_user/<userId>/` index on submit.
- Free marketplace download path read-modify-writes the full listing JSON (same race shape as L2994). [worker.ts#L2993](cloud/src/worker.ts#L2993) — see above.
- Upstream error bodies (Modal, Stripe) echoed verbatim to clients via `err(502, ... + e.message)` — low-grade infra fingerprinting. [worker.ts#L4395,L4447,L4503,L4584,L4603,L4658,L4710,L4787,L4812,L5584,L2603,L2615,L2663,L2774](cloud/src/worker.ts#L4395) — log raw server-side, return generic message + opaque request id.
- Stale "Wave 2.4 will port mvadapter" comment — creature/animal back-view still on realvis fallback, no tracking issue. [worker.ts#L3549](cloud/src/worker.ts#L3549) — either ship `MODAL_MVADAPTER_URL` or rewrite the comment as a tracked issue.
- `MODAL_MESH_URL` Env field + doc block describe an abandoned single-URL design (real reads use `MODAL_MESH_START_URL` / `MODAL_MESH_STATUS_URL`). [worker.ts#L85](cloud/src/worker.ts#L85), doc at L4723-4738 — drop the field or rewrite the comment.
- Cloud `batchCheckNsfw` stub returns `{ok, results}` but renderer iterates the envelope, polluting `_nsfwScanCache` with `'ok'`/`'results'` keys + extra grid re-render. [meshyAPI-cloud.js#L635](cloud/public/app/meshyAPI-cloud.js#L635) — return `{}`.
- `_runNsfwBackgroundScan` runs to completion on cloud against the stub and prints 5-7 `[NSFW]` lines per project per call. [index2.js#L640](cloud/public/app/index2.js#L640) — gate on `document.body.classList.contains('cloud-mode')` or implement a real `/api/nsfw-batch`.
- `_lastKnownBalance` is written, never read. [cloud-overrides.js#L769](cloud/public/app/cloud-overrides.js#L769) — delete or actually use it as optimistic UI.
- `[modalStatus]` console.log spam at OK/non-OK/catch — fires every 60s + on tool-button clicks. [cloud-overrides.js#L400,L416,L429](cloud/public/app/cloud-overrides.js#L400) — guard with `window.__modalDebug` or remove.
- `generateBackView` shim sends `assetType` while worker reads `asset_type` — analytics/logging only on the Modal path, but worth fixing to match `imageTo3D`. [meshyAPI-cloud.js#L443](cloud/public/app/meshyAPI-cloud.js#L443) — rename to `asset_type`.

## Recommendations — order of attack
1. **Fix the asset-type contract drift** (`assetType` → `asset_type` on the renderer side at [index2.js#L7096](cloud/public/app/index2.js#L7096), plus the matching back-view shim at [meshyAPI-cloud.js#L443](cloud/public/app/meshyAPI-cloud.js#L443)). One-line change, restores correct pipeline for every non-character cloud mesh.
2. **Patch the subscription invoice handler** to read metadata from `subscription_details.metadata` (or via `stripe.subscriptions.retrieve`). [worker.ts#L3282](cloud/src/worker.ts#L3282). Required before flipping subscription Prices live.
3. **Add `refundMeshSpend()` to the two `handleGenerate` catch arms** ([worker.ts#L3674](cloud/src/worker.ts#L3674), [#L3688](cloud/src/worker.ts#L3688)) and discriminate Postgres `23505` in `_processPayment` ([worker.ts#L3203](cloud/src/worker.ts#L3203)). Both are tiny, both prevent silent money/budget loss.
4. **Wire `cancelJob` to the worker job id** ([index2.js#L12918](cloud/public/app/index2.js#L12918)) and **fix "Add back photo"** to use `API.saveImageDataUrl` ([index2.js#L1955](cloud/public/app/index2.js#L1955)). Both are user-visible features currently silently broken on cloud.
5. **Make `applyOverrides` idempotent** ([cloud-overrides.js#L2141](cloud/public/app/cloud-overrides.js#L2141)) and **translate `meshTool` array params to named keys** ([meshyAPI-cloud.js#L1469](cloud/public/app/meshyAPI-cloud.js#L1469)). Cheap fixes that stop ongoing leaks (listeners/intervals/chained fetches) and stop billing users for no-op slider changes.

## Gaps in this audit
- **No runtime / behavioural verification** — every finding is static-read only. Modal endpoint contracts (`MODAL_MESH_START_URL`, `MODAL_MVADAPTER_URL`, mesh-op endpoints) were inferred from worker.ts call sites; we never hit them, so payload-shape claims (e.g. that `asset_type` is actually consumed Modal-side, that `meshTool` named-keys would be honoured) are unverified. Same for the Stripe webhook flow — no replay of a real `invoice.paid` event against the worker.
- **No rate-limit / abuse-surface audit** — we flagged individual races (uploads/day, listing downloads, market checkout) but did not enumerate which `/api/*` endpoints have *no* rate limiting at all (e.g. `/api/contact`, `/api/auth/*`, `/api/jobs/*`, NSFW stubs). A dedicated pass on `env.RATE_LIMIT_KV` usage vs. handler list is missing.
- **No DB / R2 schema audit** — Supabase tables (`jobs`, `payments`, `users`, `subscriptions`) and R2 key prefixes (`_market/`, `_meta/`, `_jobs/`) were referenced incidentally but never enumerated. Orphan-key classes beyond the marketplace one (e.g. `_jobs/` after user delete, `_meta/contact/` retention, GDPR/RTBF coverage) are unexamined.
- **Desktop-side Python pipeline scripts were not reviewed** — `scripts/*.py` (generate_front_tpose, NSFW classifier, UniRig integration, SDXL tile refine) were out of scope. Drift between desktop Python defaults and cloud Modal defaults (asset_type bias, ip_scale, prompt templates) is therefore unmeasured, despite being the historical root of "looks different on cloud vs desktop" reports.
- **No a11y, i18n, perf, or bundle-size audit** — renderer findings were correctness/parity only. We did not measure `index2.js` bundle size, time-to-interactive on cloud, keyboard-trap behaviour in the 3D modals, French/English string drift, or memory growth across long sessions (which is suggestive given the confirmed `applyOverrides` leak).
